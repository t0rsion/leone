# Efficient LLM Inference: The 2025–2026 Research Frontier

*An annotated bibliography for someone building a new research inference engine. Compiled August 2026.*

## How to read this

This covers roughly January 2025 through August 2026, deliberately skipping the settled canon (FlashAttention-1/2, PagedAttention, vLLM's continuous batching, GPTQ/AWQ, the original speculative decoding papers). Those are assumed. What follows is the material that has changed since, organised by the subsystem it touches.

Two notes on trust. First, arXiv IDs for 2026 use the `26MM.NNNNN` form; anything with a `2606`–`2608` prefix is weeks-to-months old and unreplicated, so treat author-reported speedups as upper bounds. Second, where a paper's central claim is contested I have said so rather than smoothing it over — several of the most useful results here are negative ones.

The single most important structural observation: **in 2025 the field optimised kernels; in 2026 it is optimising memory capacity and the metadata around attention.** Almost every frontier system paper below is really about where bytes live and who indexes them.

## 1. Sparse and efficient attention

### 1.1 Natively trainable sparse attention

This is where frontier labs converged. The pattern is always the same: a cheap scorer selects a subset of KV, then exact attention runs over the selection.

- **NSA — Native Sparse Attention** ([2502.11089](https://arxiv.org/abs/2502.11089), DeepSeek, Feb 2025, ACL 2025). Three branches — coarse token compression, fine-grained block selection, sliding window — trained from scratch rather than bolted on, with arithmetic intensity balanced so the sparse kernel is genuinely fast. *Engine:* needs a GQA-group-shared block-selection kernel and fused compress/select/window paths. *Maturity:* strong research, productionised lineage.
- **MoBA — Mixture of Block Attention** ([2502.13189](https://arxiv.org/abs/2502.13189), Moonshot, Feb 2025). MoE-style top-k routing over KV blocks; each query picks its own block experts, and the design flips losslessly between full and sparse. *Engine:* a gating op plus varlen block-sparse FlashAttention with per-query block lists. *Maturity:* production (Kimi).
- **InfLLM-V2** ([2509.24663](https://arxiv.org/abs/2509.24663), Sep 2025, ICLR 2026). Dense/sparse switchable attention reusing dense parameters, adapting with ~5B long-context tokens. Ships inside MiniCPM4 ([2506.07900](https://arxiv.org/abs/2506.07900)). *Engine:* a runtime dense/sparse switch keyed on sequence length. *Maturity:* production (on-device).
- **DeepSeek-V3.2 / DSA** ([2512.02556](https://arxiv.org/abs/2512.02556), Dec 2025). The full report behind DeepSeek Sparse Attention, first shipped in V3.2-Exp (Sep 2025): a lightweight "lightning indexer" scores every prefix token per query, a token selector keeps top-k, attention runs only on those. Roughly 3–6× long-context cost reduction at 128K. Critically, DSA runs **MLA in MQA mode** so a single latent is shared across all query heads — that is what makes top-k gather affordable. *Engine:* the most consequential single paper here; you need a fused low-precision indexer, a fast top-k over the KV axis, and an MLA-compatible gathered-attention kernel. Already in vLLM and SGLang. *Maturity:* production.
- **MiniMax Sparse Attention (MSA)** ([2606.13392](https://arxiv.org/abs/2606.13392), Jun 2026). Blockwise sparse attention over GQA where each GQA *group* independently selects its own top-k blocks. 28.4× less per-token attention compute at 1M; 14.2× prefill / 7.6× decode on H800. *Engine:* per-group block lists mean gather patterns diverge within a layer. *Maturity:* production (MiniMax-M3).
- **LongCat Sparse Attention** ([2608.01662](https://arxiv.org/abs/2608.01662), Meituan, Aug 2026). Streaming-aware indexing converts scattered KV picks into hardware-aligned contiguous runs; cross-layer indexing amortises indexer cost; hierarchical coarse-to-fine scoring cuts the O(L²) scan. *Engine:* the most system-aware sparse-attention design published. *Maturity:* production (LongCat-2.0, 1.6T MoE, native 1M).
- **NOSA — Native and Offloadable Sparse Attention** ([2510.13602](https://arxiv.org/abs/2510.13602), Oct 2025). Trainable sparse attention with an explicit locality constraint so CPU→GPU transfer volume stays bounded. *Engine:* directly targets the batch-size wall. *Maturity:* strong research.
- **MiniCPM-SALA** ([2602.11761](https://arxiv.org/abs/2602.11761), Feb 2026). 9B hybrid interleaving InfLLM-V2 sparse layers with Lightning Attention linear layers at 1:3. *Engine:* two coexisting state types per model with different paging semantics.

### 1.2 The indexer is the new bottleneck

Once main attention is sparse, the scorer dominates. This is the clearest 2026 trend, with at least eight independent attacks.

- **FSA — Flash Sparse Attention** ([2508.18224](https://arxiv.org/abs/2508.18224), Aug 2025, rev. Jul 2026). NSA's reference kernel only pays off with large GQA group sizes; FSA swaps the loop order (outer over KV blocks, inner over queries) for the small groups real models use. Up to 3.5× kernel latency reduction. *If you implement NSA, implement FSA's loop order instead.*
- **LiteTopK** ([2607.11976](https://arxiv.org/abs/2607.11976), Jul 2026). Sparse-attention scores concentrate narrowly in high dimensions, enabling a threshold-based fused indexer+top-k kernel that avoids DSA's global memory traffic and workspace.
- **IndexCache** ([2603.12201](https://arxiv.org/abs/2603.12201)), **You Only Index Once / CLSA** ([2606.06467](https://arxiv.org/abs/2606.06467)), **Kascade** ([2512.16391](https://arxiv.org/abs/2512.16391), also MLSys 2026). Three independent confirmations that top-k selections are highly similar across adjacent layers, so you recompute the index only at anchor layers. **Cross-layer index reuse is the most-replicated finding of 2026** — cheap, no retraining, large payoff. *Engine:* an index cache is new state with its own lifetime and eviction rules.
- **PIVOT** ([2607.24593](https://arxiv.org/abs/2607.24593), Jul 2026). Training-free DSA-indexer replacement: nearby queries pick overlapping top-k sets, so one full-prefix traversal is shared across a query group. 4× indexer speedup.
- Also: **MISA** ([2605.07363](https://arxiv.org/abs/2605.07363), indexer heads as an MoE pool), **HISA** ([2603.28458](https://arxiv.org/abs/2603.28458), block-then-token hierarchical indexing), **StreamIndex** ([2605.02568](https://arxiv.org/abs/2605.02568), memory-bounded streaming top-k — 1M context in 6.2 GB peak HBM where baselines OOM at 64K).
- **CoSA** ([2607.25291](https://arxiv.org/abs/2607.25291), Jul 2026). Argues proxy and kernel must be co-designed: at tight budgets the proxy drops salient blocks and a mechanical kernel cannot recover. *Engine:* the kernel must feed information back to selection — an API change, not an optimisation.
- **Guess-Verify-Refine** ([2604.22312](https://arxiv.org/abs/2604.22312), Apr 2026). Exact top-k for decode on Blackwell using the previous step's top-k as a prediction, narrowing by secant-style counting in 1–2 passes. Top-k is a per-decode-step latency floor even after everything else is optimised.

### 1.3 Training-free sparse attention (prefill-dominant)

- **XAttention** ([2503.16428](https://arxiv.org/abs/2503.16428), ICML 2025). The sum of antidiagonal values in a block is a cheap, accurate proxy for block importance. Up to 13.5× attention speedup; among the cheapest sparse prefill paths to add.
- **SpargeAttention** ([2502.18137](https://arxiv.org/abs/2502.18137), ICML 2025). Two-stage online filter fused into the FlashAttention inner loop rather than a precomputed mask — one kernel, no separate selection pass. Composes with SageAttention.
- **MInference 1.0** ([2407.02490](https://arxiv.org/abs/2407.02490)) and **MMInference** ([2504.16083](https://arxiv.org/abs/2504.16083), Apr 2025). Offline head classification into A-shape / Vertical-Slash / Block-Sparse with pattern-specific kernels; ~10× prefill at 1M. MMInference permutes tokens so cross-modal grid patterns become contiguous for VLMs. *Engine:* three kernel families plus an offline head-classification artifact shipped with the model.
- **FlexPrefill** ([2502.20766](https://arxiv.org/abs/2502.20766), ICLR 2025 Oral). Per-head, per-input adaptive pattern and budget via JS-divergence and cumulative-attention thresholding. *Engine:* ragged per-head work breaks static load balancing.
- **SeerAttention** ([2410.13276](https://arxiv.org/abs/2410.13276)) / **SeerAttention-R** ([2506.08889](https://arxiv.org/abs/2506.08889), ICLR 2026). A learnable gate self-distilled from the model's own attention; -R drops query pooling for autoregressive decoding and shares sparsity across GQA groups. Up to 9× over FA-3 at 90% sparsity via a TileLang decode kernel. One of the few works targeting *reasoning decode* rather than prefill.
- **Prism** ([2602.08426](https://arxiv.org/abs/2602.08426), Feb 2026). Proves that mean-pooling keys as a block proxy acts as a low-pass filter that destructively interferes with high-frequency RoPE dimensions, explaining why coarse proxies mis-rank blocks. A near-free correctness fix to a proxy nearly every block-sparse implementation uses.
- Also: **VSPrefill** ([2603.04460](https://arxiv.org/abs/2603.04460), linear-time vertical/slash indexing), **Double-P** ([2602.05191](https://arxiv.org/abs/2602.05191), hierarchical top-p instead of fixed top-k budgets), **UNIQUE** ([2605.27740](https://arxiv.org/abs/2605.27740)), **COBS** ([2607.09052](https://arxiv.org/abs/2607.09052), selection as attention-mass ranking with proved error bounds), **Full Attention Strikes Back** ([2605.16928](https://arxiv.org/abs/2605.16928), converts full to sparse in ~100 training steps, 9.36× prefill).

### 1.4 Retrieval-style, offloaded, and heterogeneous

The 2024 foundations are still the reference points: **Quest** ([2406.10774](https://arxiv.org/abs/2406.10774), page min/max metadata alongside paged KV), **InfLLM** ([2402.04617](https://arxiv.org/abs/2402.04617)), **RetrievalAttention** ([2409.10516](https://arxiv.org/abs/2409.10516), CPU ANN index over keys with explicit query-key OOD handling), **MagicPIG** ([2410.16179](https://arxiv.org/abs/2410.16179), ICLR 2025 — argues top-k is a *biased* estimator of attention output and that LSH sampling estimates it better, with CPU-side hashing and 15–18× larger batches), **ShadowKV** ([2410.21465](https://arxiv.org/abs/2410.21465), low-rank key cache on GPU, values on CPU), **DuoAttention** ([2410.10819](https://arxiv.org/abs/2410.10819), retrieval vs streaming heads with per-head KV budgets), **TokenSelect** ([2411.02886](https://arxiv.org/abs/2411.02886), token-level criticality with a selection-reuse cache).

The 2025–26 systems work is where it gets interesting:

- **RetroInfer** ([2505.02922](https://arxiv.org/abs/2505.02922), MSR, May 2025). Treats the KV cache as a vector storage system with a "wave index" and a GPU-CPU buffer manager overlapping movement with compute; 4.4× decoding throughput at 120K. The clearest blueprint for *KV cache as a database*.
- **LServe** ([2502.14866](https://arxiv.org/abs/2502.14866), MIT HAN Lab, Feb 2025). Unifies static streaming-head sparsity and dynamic page selection in **one** blocked-sparse kernel across prefill and decode.
- **SparDA** ([2606.04511](https://arxiv.org/abs/2606.04511), Jun 2026). Adds a fourth per-layer projection ("Forecast") predicting which KV blocks the *next* layer needs, so CPU→GPU prefetch overlaps with current-layer compute.
- **HiSparse** ([2608.07009](https://arxiv.org/abs/2608.07009), Aug 2026). Names the real wall: top-k decode is compute-cheap, but engines keep the whole KV in HBM so every position stays *selectable*. An exact, indexer-agnostic hierarchical cache (spanning DSA, NSA, Quest) with full history in host memory and a bounded GPU footprint. Arguably the highest-leverage systems idea of 2026.
- **OasisKV** ([2608.08097](https://arxiv.org/abs/2608.08097), Aug 2026). Independent confirmation of the same direction, using **speculative-decoding lookahead tokens as a prefetch oracle** for KV blocks beyond HBM. 1.69–2.1× throughput. Speculation repurposed as a memory-hierarchy predictor is a genuinely new mechanism.
- **KARAT** ([2608.03555](https://arxiv.org/abs/2608.03555)) and **Salca** ([2604.24820](https://arxiv.org/abs/2604.24820)) push the KV off the GPU entirely into processing-near-memory.
- **Dynamic Sparse Attention: Access Patterns and Architecture** ([2603.13430](https://arxiv.org/abs/2603.13430), Mar 2026). The memory-system reality check — DSA's fragmented, volatile working set produces blocking LLC misses that erase theoretical bandwidth savings. This is why LongCat and HiSparse chase contiguity.

### 1.5 Quantized attention kernels

- **SageAttention** ([2410.02367](https://arxiv.org/abs/2410.02367)) → **SageAttention2** ([2411.10958](https://arxiv.org/abs/2411.10958)) → **SageAttention2++** ([2505.21136](https://arxiv.org/abs/2505.21136)). Quantize QK^T and PV with smoothing and per-thread scales. Drop-in FlashAttention replacements; production-deployed across video/image generation stacks.
- **SageAttention3** ([2505.11594](https://arxiv.org/abs/2505.11594), NeurIPS 2025 Spotlight). Microscaling FP4 attention on Blackwell tensor cores, ~1038 TOPS on RTX5090 (~5× FA-2), plus an 8-bit training exploration extended by **SageBwd** ([2603.02170](https://arxiv.org/abs/2603.02170)). If you target B200/GB200 this is the ceiling.
- **FlashAttention-4** ([2603.05451](https://arxiv.org/abs/2603.05451), MLSys 2026). FA-3 targeted Hopper; Blackwell scales *asymmetrically* — tensor-core throughput doubles while shared memory and exponential units barely move. FA-4 redesigns softmax/exp scheduling and memory staging around that imbalance. **Every 2026 sparse-attention speedup should be measured against FA-4, not FA-3.**

### 1.6 Accuracy and scaling studies

- **The Sparse Frontier** ([2504.17768](https://arxiv.org/abs/2504.17768), Apr 2025, rev. Jun 2026). The largest empirical study of training-free sparse attention: six methods, multiple families, up to 128K, sparsity to 0.95, nine tasks. Key isoFLOPS finding — for very long sequences a *larger* model with high sparsity beats a smaller dense model, and no single method wins across tasks. Also establishes that **decode is far less sparsity-tolerant than prefill.** Essential reading before choosing default budgets.
- **vAttention: Verified Sparse Attention** ([2510.05688](https://arxiv.org/abs/2510.05688), Oct 2025). Top-k and random sampling are complementary (top-k on peaked distributions, sampling on flat ones); unifies them with **user-specified approximation guarantees on the attention output**. The first sparse attention with an accuracy knob you can expose as an SLO. (Not to be confused with the ASPLOS'25 memory-management paper of the same name, §9.3.)
- **Understanding Sparse Attention Selectivity via Counterfactual Evaluation** ([2608.01676](https://arxiv.org/abs/2608.01676), Aug 2026). Audits *what content* block-sparse routing discards using dense-calibrated probe cards. Route replay changed output decisions in 13 of 16 model-condition cells. You need per-content regression tests, not just RULER scores.
- **Efficient Attention Mechanisms for LLMs: A Survey** ([2507.19595](https://arxiv.org/abs/2507.19595), rev. Feb 2026). The best current taxonomy of linear and sparse attention families.

## 2. KV cache

### 2.1 Benchmarks and critiques — read these first

The most valuable cluster in the whole KV literature is the one telling you compression does not work as advertised.

- **KV Cache Compression, But What Must We Give in Return?** ([2407.01527](https://arxiv.org/abs/2407.01527), EMNLP 2024). The original systematic demolition: headline compression ratios hide task-specific collapse.
- **SCBench** ([2412.10319](https://arxiv.org/abs/2412.10319), Microsoft, ICLR 2025). Evaluates the full KV lifecycle in *shared-context multi-turn* settings rather than single requests. Sub-O(n) memory methods degrade badly across turns; O(n) sparse encoding holds up. Because it models how vLLM/SGLang actually run with prefix caching, its conclusions transfer. **This is the benchmark that should gate any eviction feature.**
- **The Pitfalls of KV Cache Compression** ([2510.00231](https://arxiv.org/abs/2510.00231), Oct 2025). Compression degrades *unevenly* across instructions — some system instructions are silently dropped while aggregate accuracy looks fine.
- **KVDiagnosis** ([2608.09412](https://arxiv.org/abs/2608.09412), Aug 2026). 25 methods into five mechanism families, 59,800 compressed runs, insisting no compressor defines another's test set. 63.2% of methods have low or partial diagnostic coverage.
- **Does Accuracy Equal Evidence?** ([2608.01631](https://arxiv.org/abs/2608.01631), Aug 2026). Compressed models keep the right *answer* while the supporting reasoning degrades. If you serve visible CoT, accuracy metrics are lying to you.
- **Benchmarking KV-Cache Optimizations across Task Quality and System Performance** ([2607.05399](https://arxiv.org/abs/2607.05399), May 2026). Compression ratio does not predict system performance; KIVI4 is the consistent-quality choice, SnapKV wins throughput at long context. Argues explicitly against a single default compressor.
- **The risk of KV cache compression** ([2607.01520](https://arxiv.org/abs/2607.01520), Jul 2026). Derives the **minimax risk** of KV compression as a function of intrinsic compressibility — tells you when a cache is simply not compressible.
- **Attention Degradation, Function Token Anchoring, and the Limits of Attention-Based Intervention** ([2607.20524](https://arxiv.org/abs/2607.20524)). A direct mechanistic challenge to the H2O/SnapKV scoring family.
- Surveys: **KV Cache Management** ([2412.19442](https://arxiv.org/abs/2412.19442)), **From Tensor Buffer to Distributed Memory Hierarchy** ([2607.02574](https://arxiv.org/abs/2607.02574), Jun 2026 — classifies 30+ *systems* by locality/lifetime/ownership/substrate into five recurring architectures; the best design-space map for a storage layer), **System-Aware KV Cache Optimization** ([2607.08057](https://arxiv.org/abs/2607.08057), ACL 2026 Findings).

### 2.2 Eviction and selection

Foundations still in production: **SnapKV** ([2404.14469](https://arxiv.org/abs/2404.14469)), **H2O** ([2306.14048](https://arxiv.org/abs/2306.14048)), **StreamingLLM** ([2309.17453](https://arxiv.org/abs/2309.17453)), **PyramidKV** ([2406.02069](https://arxiv.org/abs/2406.02069)), **Ada-KV** ([2407.11550](https://arxiv.org/abs/2407.11550), NeurIPS 2025 — reallocates budget *across heads*, the cheapest real win and it composes as a plug-in).

- **Expected Attention** ([2510.00636](https://arxiv.org/abs/2510.00636), NVIDIA, Oct 2025). Closed-form estimate of how *future* queries will attend, so scoring never needs a materialized attention matrix. **FlashAttention-compatible by construction** — which is the single biggest integration filter. Ships with **KVPress**, NVIDIA's 20+-method library and HF leaderboard, now the de facto A/B harness.
- **KVzip** ([2505.23416](https://arxiv.org/abs/2505.23416), May 2025). Query-agnostic compression scored on context reconstructability. **Query-agnostic is the only variant compatible with prefix-cache reuse** — query-aware presses silently destroy hit rate. Spawned KVzap ([2601.07891](https://arxiv.org/abs/2601.07891)) and FastKVzip ([2601.17668](https://arxiv.org/abs/2601.17668)).
- **CapKV** ([2604.25975](https://arxiv.org/abs/2604.25975), Apr 2026). Derives a closed-form mutual-information objective for effective information capacity, showing existing heuristics are all approximations of one capacity-maximization principle, realised via leverage scores. The unifying theory paper. See also **Compactor** ([2507.08143](https://arxiv.org/abs/2507.08143)) and **CriticalKV** ([2502.03805](https://arxiv.org/abs/2502.03805)).
- **AnchorKV** ([2608.02901](https://arxiv.org/abs/2608.02901), Aug 2026). 20× compression **without discarding any token**: a small anchor set stored exactly, every other token expressed as nearest-anchor plus a selectively refined residual. 99% of full-cache score at 70B. Sidesteps the entire eviction critique, and the anchor/residual split maps onto a two-tier memory layout.
- **RestoreKV** ([2608.01247](https://arxiv.org/abs/2608.01247), Aug 2026). Pairs eviction with learned LoRA-based *restoration* tokens. The "evict + repair" pattern is the most promising 2026 direction for making aggressive budgets safe.
- Also: **Epiphany-Aware eviction** ([2606.26472](https://arxiv.org/abs/2606.26472), scores by representation change, never materialising attention), **Error Certificates** ([2607.21475](https://arxiv.org/abs/2607.21475), per-request statistical bounds), **DistillCache** ([2608.08878](https://arxiv.org/abs/2608.08878), RL policy rewarded by KL to the uncompressed distribution), **RippleKV** ([2608.08684](https://arxiv.org/abs/2608.08684)), **LAVa** ([2509.09754](https://arxiv.org/abs/2509.09754)) and **EvolKV** ([2509.08315](https://arxiv.org/abs/2509.08315)) on budget allocation.

### 2.3 KV quantization

The 2026 story is that the field moved from scalar per-token INT4 into **transform coding**, and broke the 2-bit cliff.

- **KIVI** ([2402.02750](https://arxiv.org/abs/2402.02750), ICML 2024). The per-channel-key / per-token-value asymmetry is the most reused finding in the line; KIVI4 remains the robust default.
- **RotateKV** ([2501.16383](https://arxiv.org/abs/2501.16383), IJCAI 2025). Outlier-aware adaptive rotations; rotation is now the standard prerequisite for sub-4-bit KV.
- **OSCAR** ([2605.17757](https://arxiv.org/abs/2605.17757), May 2026). Attention-aware covariance computed **offline** yields fixed rotations and clipping thresholds — zero runtime rotation cost. ~8× memory, up to 7× throughput at high batch, validated 4B→358B to 128K, **with custom integer kernels for SGLang and vLLM**. The most engine-ready 2-bit KV paper.
- **SPECTRA** ([2608.07915](https://arxiv.org/abs/2608.07915), Aug 2026). Rotates the cache into its own statistical eigenbasis where a small fraction of channels carries almost all information, then allocates bits non-uniformly. Training-free codec: near-lossless at 4×, competitive at 8×, up to 12×. Names and breaks the "2-bit cliff."
- **Transform Coding for KV** ([2608.14191](https://arxiv.org/abs/2608.14191)) and **Codec-Gauge** ([2607.20538](https://arxiv.org/abs/2607.20538)) confirm the field is converging on classical rate-distortion.
- **CommVQ** ([2506.18879](https://arxiv.org/abs/2506.18879), Jun 2025). Codebook VQ that **commutes with RoPE**, which is what makes VQ deployable. **KVLinC** ([2510.05373](https://arxiv.org/abs/2510.05373)) adds linear correction adapters for key-quantization error.
- Sub-1-bit frontier: **GSRQ** ([2607.01065](https://arxiv.org/abs/2607.01065)) and **RaBitQCache** ([2606.31519](https://arxiv.org/abs/2606.31519)) — the latter pairs binary codes with adaptive top-p retrieval so *the compressed form is the selector*. **RoPE-Aware Bit Allocation** ([2606.24033](https://arxiv.org/abs/2606.24033)) allocates bits per RoPE frequency block; cheap and orthogonal. **WitCert** ([2607.28699](https://arxiv.org/abs/2607.28699)) computes provably sound per-layer distortion bounds *during serving* — the observability primitive you want before enabling 2-bit on production traffic. **Kitty** (MLSys 2026) does 2-bit KV with dynamic channel-wise precision boost.

### 2.4 Low-rank, latent, and MLA conversion

- **TransMLA** ([2502.07864](https://arxiv.org/abs/2502.07864), Feb 2025, NeurIPS 2025). Converts any GQA model (LLaMA, Qwen, Gemma, Mistral) into MLA with full DeepSeek compatibility, via RoRoPE (PCA-concentrate positional info), FreqFold, and balanced KV compression. 93% KV compression on LLaMA-2-7B, ~10× speedup at 8K after ~6B recovery tokens. Proves GQA is always representable as MLA at equal cache cost, but not conversely. **The highest-leverage structural item on this list** — it lets existing open weights run on your MLA-optimised kernel path instead of maintaining two attention backends. The integration hazard is the non-standard partial/decoupled RoPE, not the MLA math.
- **MHA2MLA** (Feb 2025) extends conversion to plain MHA via partial-RoPE and low-rank joint SVD. **X-EcoMLA** upcycles pretrained attention into MLA. **CARE** ([2603.17946](https://arxiv.org/abs/2603.17946)) does covariance-aware rank-enhanced conversion. **Attention Editing** ([2604.05688](https://arxiv.org/abs/2604.05688), Apr 2026) is a general cross-architecture conversion framework — if post-hoc conversion becomes routine, attention architecture stops being a training-time commitment.
- **Palu** ([2407.21118](https://arxiv.org/abs/2407.21118), ICLR 2025). SVD-decomposes K/V projections and caches the latent; the reference design for "cache the latent, not the tensor," and it composes with quantization.
- **xKV** ([2503.18893](https://arxiv.org/abs/2503.18893), Mar 2025). Jointly factorizes grouped *layers* into a shared low-rank subspace via CKA-aligned singular vectors — bridges the low-rank and cross-layer families.
- **OjaKV** ([2509.21623](https://arxiv.org/abs/2509.21623)) tracks the subspace online with Oja's rule, fixing offline-SVD drift on OOD context; **VarRate** ([2607.15498](https://arxiv.org/abs/2607.15498)) and **JoLT** ([2607.12550](https://arxiv.org/abs/2607.12550)) are variable-rate low-rank variants.
- **GQLA** ([2605.15250](https://arxiv.org/abs/2605.15250), May 2026). MLA with dual decoding paths switchable per hardware without retraining — MLA's absorbed and non-absorbed forms have opposite compute/memory profiles, and this makes the choice a runtime knob. **QK-Normed MLA** ([2606.16310](https://arxiv.org/abs/2606.16310)) resolves the known QK-norm/latent-cache incompatibility. **LAGA** ([2607.17644](https://arxiv.org/abs/2607.17644)) documents why Megatron-Core forbids MLA absorption under sequence parallelism, and fixes it.

### 2.5 Cross-layer and cross-head sharing

- **A Systematic Study of Cross-Layer KV Sharing** ([2410.14442](https://arxiv.org/abs/2410.14442)). The only apples-to-apples comparison of CLA, YOCO, LCKV, and MLKV. Read before picking a pattern.
- **Stochastic KV Routing** ([2604.22782](https://arxiv.org/abs/2604.22782), Apr 2026) randomizes cross-layer attention *during training* so sharing degree becomes a deploy-time knob — one checkpoint, many memory/quality operating points, the most engine-friendly framing here. Also **YOCO++** ([2604.13556](https://arxiv.org/abs/2604.13556)), **CommonKV** ([2508.16134](https://arxiv.org/abs/2508.16134)), **KV-Pipe** ([2608.15943](https://arxiv.org/abs/2608.15943), sharing as a pipeline-balancing knob).

### 2.6 Offloading, tiering, and KV-as-a-service

- **Mooncake** ([2407.00079](https://arxiv.org/abs/2407.00079), FAST 2025 **Best Paper**). Separated prefill/decode clusters plus a disaggregated KVCache pool built from otherwise-idle CPU DRAM, SSD, and NIC capacity, with a cache-aware global scheduler. Runs Kimi at 100B+ tokens/day. The canonical production reference architecture; its Transfer Engine is now a pluggable backend in SGLang and vLLM.
- **LMCache** ([2510.09665](https://arxiv.org/abs/2510.09665), Oct 2025). Pulls KV out of GPU memory into a pluggable layer with backends for CPU RAM, SSD, Redis/Valkey, Mooncake, InfiniStore, S3, NIXL, GDS; supports P/D disaggregation and cross-engine sharing. **Build against LMCache's interface rather than a bespoke offload path.**
- **CacheBlend** (EuroSys 2025, [2405.16444](https://arxiv.org/abs/2405.16444)). Reuses KV for *non-prefix* chunks and selectively recomputes only the tokens whose cross-attention actually changed. Prefix caching only helps when shared text is a literal prefix; RAG almost never is. Shipped inside LMCache.
- **Strata** (OSDI 2026). Shows naive hierarchical caching across HBM/DRAM/SSD becomes **I/O-bound because fragmented KV layouts produce small, bandwidth-wasting transfers** — and redesigns layout and prefetch accordingly. The most actionable single result for anyone writing an offload path. Companions at OSDI'26: **ECHO** (lossless prefetching for native-sparse-attention models) and **No Buffer, No Bottleneck** (zero-copy offload).
- **KVSwap** ([2511.11907](https://arxiv.org/abs/2511.11907), MobiSys 2026). CPU-GPU offload designs fail on *disk* because fine-grained access fragments into tiny reads; keeps accuracy loss to 1–4% where ShadowKV loses 5–52% in disk settings. The access-granularity lesson generalises to any high-per-access-cost tier.
- **ShadowServe** ([2509.16857](https://arxiv.org/abs/2509.16857)) moves decompression off the critical GPU path — remote cache hits can be *slower* than recompute if fetch steals SM time. **FlexiCache** ([2511.00868](https://arxiv.org/abs/2511.00868), MLSys 2026) offloads only temporally stable heads. **vToken** ([2608.13263](https://arxiv.org/abs/2608.13263)) enables token-granularity reclamation; **GraniKV** ([2608.15584](https://arxiv.org/abs/2608.15584)) mixes page sizes because one size is wrong for agent fan-out.
- **SAC** ([2606.19746](https://arxiv.org/abs/2606.19746)) and **TraCT** ([2512.18194](https://arxiv.org/abs/2512.18194)) argue RDMA wastes bandwidth fetching whole prefixes when sparse attention touches a few percent, and that **CXL's cache-line granularity is what sparse decoding actually needs.** Sparse attention and CXL are strongly complementary.
- Position-independent caching: **HYPIC** ([2607.01299](https://arxiv.org/abs/2607.01299), 3.25× TTFT for hybrid-attention models) and **Irminsul** ([2605.05696](https://arxiv.org/abs/2605.05696), MLA-native). Naive radix prefix caching is **unsound** for hybrid and latent-attention models — a correctness issue, not just perf. See also SGLang's **Unified Radix Cache** (Aug 2026) and **Marconi** (MLSys 2025).
- **Cross-Model KV Cache Transfer** ([2608.03893](https://arxiv.org/abs/2608.03893), Aug 2026) and **DroidSpeak** (NSDI 2026). A receiver model reuses a sibling model's KV via a closed-form linear map, skipping prefill entirely. Highest-variance, highest-upside result of 2026 — it changes routing economics for size-tiered deployments.
- **Security, act on this now:** prefix-cache hit timing lets one tenant reconstruct another's prompts. Attack: **Agent-Assisted Side-Channel Attacks on Non-Prefix KV Cache in RAG** ([2606.21842](https://arxiv.org/abs/2606.21842)). Defences: **Governing the KV Cache** ([2608.09225](https://arxiv.org/abs/2608.09225), per-principal salts), **CacheSolidarity** ([2603.10726](https://arxiv.org/abs/2603.10726)), **PrefixShield** ([2608.01657](https://arxiv.org/abs/2608.01657), cross-tenant eviction fairness). Treat global cache sharing as a security boundary.

### 2.7 Reasoning traces and agents

- **R-KV** ([2505.24133](https://arxiv.org/abs/2505.24133), NeurIPS 2025). Combines attention importance with an online **redundancy** score over key vectors, because reasoning traces repeat themselves. ~100% of full-cache performance at 10% cache where baselines reach 60%. The insight that CoT redundancy is a *different signal* from importance founded this subfield.
- **ThinKV** ([2510.01290](https://arxiv.org/abs/2510.01290)). Segments the trace into "thoughts," assigns precision by thought importance, progressively evicts superseded thoughts. Near-lossless at <5% of original cache, 5.8× throughput. Thought-level granularity is both more effective and cheaper than token-level.
- Also **Which Heads Matter for Reasoning?** ([2510.08525](https://arxiv.org/abs/2510.08525)), **SkipKV** ([2512.07993](https://arxiv.org/abs/2512.07993), MLSys 2026, skips KV generation *and* storage), **KV-Rescue** ([2608.15797](https://arxiv.org/abs/2608.15797)).
- **Inference-Time Hyper-Scaling with KV Cache Compression** ([2506.05345](https://arxiv.org/abs/2506.05345), Jun 2025). Spend the memory you save on *more parallel reasoning samples* — reframes compression as a throughput-for-accuracy trade rather than a pure loss.
- **Practical Online KV Cache Compaction for LLM Agents** ([2608.00902](https://arxiv.org/abs/2608.00902), Aug 2026). **Immediate compaction hurts; delaying until the agent's future queries are visible recovers most of the gap.** Directly contradicts the natural instinct to compact at turn boundaries. **CommitKV** ([2608.07855](https://arxiv.org/abs/2608.07855)) distinguishes dormant from completed context via agent commit transitions.
- **What to Keep, What to Forget: A Rate-Distortion View of Memory Compaction** ([2607.08032](https://arxiv.org/abs/2607.08032)). Unifies KV eviction, quantization, prompt compression, and agent memory under one rate-distortion objective — suggesting a single budget allocator across all four. See also **TriRoute** ([2607.06601](https://arxiv.org/abs/2607.06601)) and **MoE-nD** ([2604.17695](https://arxiv.org/abs/2604.17695)), which *learn* per-layer (eviction, key-bits, value-bits) tuples under a global budget. This is where the field is heading.
- Multimodal: **VL-Cache** ([2410.23317](https://arxiv.org/abs/2410.23317)), **InfiniPot-V** ([2506.15745](https://arxiv.org/abs/2506.15745)), **Frequency-Domain-Guided Outlier-KV** ([2511.16786](https://arxiv.org/abs/2511.16786), FlashAttention-compatible by design), **VideoMLA** ([2605.30351](https://arxiv.org/abs/2605.30351), 92.7% per-token KV reduction), **StreamMem** ([2508.15717](https://arxiv.org/abs/2508.15717), query-agnostic bounded memory for streaming video).

## 3. Speculative and parallel decoding

### 3.1 Reality checks first

Three 2026 papers converge on one lesson: **a static draft length is a bug.** **Speculative Decoding: Performance or Illusion?** ([2601.11580](https://arxiv.org/abs/2601.11580); also MLSys 2026) measures n-gram/EAGLE/EAGLE-3/MTP inside vLLM and finds *target-model verification dominates execution time*, with acceptance length swinging by output position and dataset. **SPEED-Bench** ([2604.09557](https://arxiv.org/abs/2604.09557)) shows synthetic benchmarks overestimate real speedup and that optimal draft length is a function of batch size. **Nightjar** ([2512.22420](https://arxiv.org/abs/2512.22420)) builds the controller that *disables speculation entirely under compute-bound load* — speculation is a memory-bound-regime optimisation and goes negative at high batch. Background: the **Speculative Decoding survey** ([2502.19732](https://arxiv.org/abs/2502.19732)) and the test-time-scaling benchmark **Scaling Up, Speeding Up** ([2509.04474](https://arxiv.org/abs/2509.04474), ICLR 2026), which quantifies how different reasoning traces look from chat. On correctness, **Revisiting Lossy Verification** ([2607.26627](https://arxiv.org/abs/2607.26627)) catalogues how relaxed rejection sampling distorts the output distribution.

### 3.2 The EAGLE line

**EAGLE-3** ([2503.01840](https://arxiv.org/abs/2503.01840), Mar 2025, NeurIPS 2025) is the baseline everyone reports against: it drops feature prediction for direct token prediction plus multi-layer feature fusion, with a "training-time test" that simulates multi-step self-feedback so the drafter benefits from data scaling. Shipped in vLLM, SGLang, TensorRT-LLM with pretrained heads for Llama 4, Qwen 2.5/3, DeepSeek-V3, GLM. Its intellectual ancestor is **HASS** ([2408.15766](https://arxiv.org/abs/2408.15766), ICLR 2025, harmonized-objective distillation fixing train/decode mismatch), and **Falcon** ([2412.12639](https://arxiv.org/abs/2412.12639), AAAI 2025) is the canonical semi-autoregressive drafter that block-diffusion drafting descends from.

Successors worth adopting: **P-EAGLE** ([2602.01469](https://arxiv.org/abs/2602.01469), Feb 2026 — parallel multi-token drafting via a learnable shared hidden state, 1.10–1.36× over autoregressive EAGLE-3, **already implemented in vLLM**, validated 20B–120B); **Draft-OPD** ([2605.29343](https://arxiv.org/abs/2605.29343), on-policy distillation of the drafter against the target's own decode distribution, **+23% acceptance length over EAGLE-3** — the largest single training-recipe win); **FastEagle** ([2509.20416](https://arxiv.org/abs/2509.20416), non-autoregressive cascaded drafter that beats EAGLE-3 on *wall-clock*, not just acceptance); **SlimSpec** ([2605.10453](https://arxiv.org/abs/2605.10453), low-rank drafter LM-head — a safer alternative to vocabulary pruning, which SPEED-Bench criticizes); **SpecBlock** ([2605.07243](https://arxiv.org/abs/2605.07243)); **JetSpec** ([2606.18394](https://arxiv.org/abs/2606.18394)); **Speculative Pipeline Decoding** ([2605.30852](https://arxiv.org/abs/2605.30852), hides drafter latency in pipeline bubbles). For stateful models, **Bole** ([2608.01651](https://arxiv.org/abs/2608.01651), 4.72× on hybrid attention) and **SpecLA** ([2607.16673](https://arxiv.org/abs/2607.16673)) solve state rollback on rejection, which is much harder than KV truncation.

### 3.3 MTP heads and self-speculation — the free win

Native MTP heads now ship with DeepSeek-V3 ([2412.19437](https://arxiv.org/abs/2412.19437), whose *sequential causal-chain* MTP module is what GLM and Qwen3-Next copied), Qwen3-Next, Qwen3.5, GLM-4.5/4.6, MiniMax-M2, Nemotron 3, Ling-1T, Step 3.5 Flash. vLLM auto-detects them from config. **Nemotron 3** ([2512.20856](https://arxiv.org/abs/2512.20856)) reports ~97% acceptance on the first two predicted tokens. Note that HF Transformers generally does *not* expose these heads, so an engine is the only place the gain is realizable.

Improving them: **FastMTP** ([2509.18362](https://arxiv.org/abs/2509.18362), position-shared heads, 2.03×), **Self-Distillation for MTP** ([2603.23911](https://arxiv.org/abs/2603.23911)), **AdaMTP** ([2608.00434](https://arxiv.org/abs/2608.00434), training-time adaptive horizon) and **EntMTP** ([2606.27550](https://arxiv.org/abs/2606.27550), runtime entropy-guided depth). **Windowed-MTP** ([2607.21535](https://arxiv.org/abs/2607.21535)) applies a sliding window to *draft* attention only while keeping full-attention verification, cutting 28–44% of per-decode cost at million-token context.

Drafter-free self-speculation: **Direct Multi-Token Decoding** ([2510.11958](https://arxiv.org/abs/2510.11958)) exploits layer specialisation to generate several tokens by re-running only the late layers — zero added weights, ~2× on Qwen3-4B. **Set Block Decoding** ([2509.04185](https://arxiv.org/abs/2509.04185)) fuses next-token and masked-token prediction so non-consecutive tokens sample in parallel with **exact** KV caching. **A Sparse Glimpse of the Whole** ([2607.27735](https://arxiv.org/abs/2607.27735)) drafts using the same model over a sparsified KV cache. **Component-Aware Self-Speculative Decoding in Hybrid LMs** ([2605.01106](https://arxiv.org/abs/2605.01106)) uses the SSM subgraph as a zero-cost draft and finds **parallel hybrids get 18× higher acceptance than sequential hybrids** — a strategy unique to hybrid architectures. MoE-specific: **Adaptive Verification for MoE Speculative Decoding** ([2605.00342](https://arxiv.org/abs/2605.00342)), **AcceptMoE** ([2608.02989](https://arxiv.org/abs/2608.02989)), **S2-MoE** ([2608.15018](https://arxiv.org/abs/2608.15018)).

### 3.4 Drafter-free retrieval

**SAM-Decoding** ([2411.10666](https://arxiv.org/abs/2411.10666), ACL 2025) uses a suffix automaton for **exact longest-suffix match in O(1) amortized**, with adaptive fallback — the strongest zero-model drafter, no GPU weights at all. **RACER** ([2604.14885](https://arxiv.org/abs/2604.14885), Apr 2026) fuses retrieved exact patterns with logit-driven future cues, training-free, >2× — the easiest thing to ship first. **When, What, and How** ([2511.01282](https://arxiv.org/abs/2511.01282)) turns retrieval drafting from a hack into a designed component (+33% over EAGLE-2). **Oilbird** ([2608.03839](https://arxiv.org/abs/2608.03839), Aug 2026) uses the verifier's *already-computed* hidden states as a **semantic** draft source, generalising past the copy-heavy workloads where n-gram wins.

### 3.5 Serving-side and RL rollouts

Per-request speculation is now a scheduling parameter: **AdaServe** ([2501.12162](https://arxiv.org/abs/2501.12162), EuroSys 2026, SLO-customized speculation), **SpecServe** ([2503.05096](https://arxiv.org/abs/2503.05096)), **FASER** ([2604.20503](https://arxiv.org/abs/2604.20503), overlaps draft and verify via spatial GPU multiplexing), **DSpark** ([2607.05147](https://arxiv.org/abs/2607.05147)), **An Interpretable Latency Model for Speculative Decoding** ([2605.15051](https://arxiv.org/abs/2605.15051)). **StarSD** ([2601.21622](https://arxiv.org/abs/2601.21622)) shares one drafter across many targets; **SPECTRE** ([2605.08151](https://arxiv.org/abs/2605.08151)) reuses idle fleet models as remote drafters. **AngelSpec** ([2607.25852](https://arxiv.org/abs/2607.25852)) co-specializes MTP *and* block-diffusion drafters in one runtime — the closest thing to a production blueprint for where this is heading.

RL rollouts are the newest application. The founding idea, **SPEC-RL** ([2509.23232](https://arxiv.org/abs/2509.23232)), is that the previous policy checkpoint is a free, extremely well-aligned drafter. **Beat the Long Tail** ([2511.13841](https://arxiv.org/abs/2511.13841), also MLSys 2026) targets stragglers rather than the median, since rollout batches are dominated by a few long sequences. **Taming the Long-Tail** ([2511.16665](https://arxiv.org/abs/2511.16665)) continuously adapts the drafter as the policy drifts. **System-Integrated Speculative Decoding for RL Rollouts** ([2604.26779](https://arxiv.org/abs/2604.26779)) is the most deployable: integrated into NeMo-RL + vLLM with sync and async pipelines, distribution-preserving, 1.8× at 8B. See also **ReSpec** and **Cascade** (both MLSys 2026), **EfficientRollout** ([2606.18967](https://arxiv.org/abs/2606.18967)), **SpecRoll** ([2608.04962](https://arxiv.org/abs/2608.04962)).

### 3.6 Parallel decoding

**PARD** ([2504.18583](https://arxiv.org/abs/2504.18583), Apr 2025) does parallel draft-model adaptation with Conditional Drop-token, and crucially **one drafter serves an entire target-model family** — train once per family, not per checkpoint. 3.67× on Llama-3.1-8B, 1.15× faster than EAGLE-3. **Jacobi Forcing** ([2512.14681](https://arxiv.org/abs/2512.14681)) is the modern CLLM successor, distilling an AR model into a parallel decoder that **keeps causal attention**, so KV cache and kernels are unchanged (up to 4.5×). **Set Diffusion** ([2607.01775](https://arxiv.org/abs/2607.01775)) offers a tunable dial between AR and diffusion via flexible-position token sets with per-step KV updates. **Any-Subset Speculative Decoding** ([2504.20456](https://arxiv.org/abs/2504.20456)) and **Parallel Sampling via Autospeculation** ([2511.07869](https://arxiv.org/abs/2511.07869)) give the correctness theory. Contrarian: **Autoregressive Models Rival Diffusion at Any-Order Generation** ([2601.13228](https://arxiv.org/abs/2601.13228)) undercuts diffusion's main claimed advantage — read before betting the stack.

## 4. Diffusion language models

### 4.1 Models

**LLaDA 8B** ([2502.09992](https://arxiv.org/abs/2502.09992)) is the reference open dLLM, aligned by **LLaDA 1.5** ([2505.19223](https://arxiv.org/abs/2505.19223), VRPO fixes the high-variance ELBO estimates that break RLHF for masked diffusion). **Dream 7B** ([2508.15487](https://arxiv.org/abs/2508.15487)) is the other canonical open model and the origin of AR-initialization. **Mercury** ([2506.17298](https://arxiv.org/abs/2506.17298), Inception Labs) is the commercial proof point at **1109 tok/s on H100** — that is the bar an AR engine has to beat. Gemini Diffusion has no paper.

The decisive 2026 shift is that **AR→diffusion conversion replaced from-scratch diffusion pretraining**. **Block Diffusion / BD3-LM** ([2503.09573](https://arxiv.org/abs/2503.09573), ICLR 2025 **oral**) is the foundational formulation — flexible-length generation *with* KV caching and parallel sampling — and is the reason dLLMs can cache at all. **SDAR** ([2510.06303](https://arxiv.org/abs/2510.06303)) adapts pretrained AR models into blockwise diffusion (sequential across blocks, parallel within), explicitly arguing AR pretraining is more compute-efficient and parallelism should be bought cheaply at the end. **Fast-dLLM v2** ([2509.26328](https://arxiv.org/abs/2509.26328)) does the conversion on **~1B tokens**, 500× less than Dream's 580B. **LLaDA2.0** ([2512.15745](https://arxiv.org/abs/2512.15745)) scales conversion to 100B with open weights; **DiffusionGemma** ([2608.00146](https://arxiv.org/abs/2608.00146), 256-token blocks in parallel) and **LLaDA MoE v2** ([2608.03457](https://arxiv.org/abs/2608.03457)) are the newest open artifacts. **Efficient-DLM** ([2512.14067](https://arxiv.org/abs/2512.14067)) is currently the cheapest conversion path.

### 4.2 Serving dLLMs

**Fast-dLLM** ([2505.22618](https://arxiv.org/abs/2505.22618), NVlabs) is the most-cited dLLM inference paper: a block-wise **approximate** KV cache for bidirectional attention plus confidence-aware parallel decoding, up to 27.6× throughput, training-free. **dKV-Cache** ([2505.15781](https://arxiv.org/abs/2505.15781)) contributes the "delayed caching" insight reused everywhere; **dLLM-Cache** ([2506.06295](https://arxiv.org/abs/2506.06295), ICML 2026) adds a static prompt cache plus similarity-guided selective recomputation (9.1× FLOPs reduction). **Elastic-Cache** ([2510.14973](https://arxiv.org/abs/2510.14973)) answers the correctness question Fast-dLLM's approximate cache leaves open, via an attention-aware refresh test. **Fast-dLLM++** ([2606.02955](https://arxiv.org/abs/2606.02955)) fixes the weakest-token threshold rule — the main quality leak in parallel commits — using the sorted confidence profile.

Two 2026 findings matter most to an engine builder. **WeDLM** ([2512.22737](https://arxiv.org/abs/2512.22737)) topologically reorders observed tokens so **standard causal attention and exact prefix KV caching apply** — if it holds up, dLLMs run on unmodified AR kernels. And **Sangam** ([2607.04206](https://arxiv.org/abs/2607.04206)) demonstrates that **dLLM serving is governed by the same prefill/decode interference and partitioning laws as AR serving**, so your scheduler mostly transfers. **BlockServe** ([2607.08930](https://arxiv.org/abs/2607.08930)) handles convergence heterogeneity, which stalls naive continuous batching. Also: **D2F** ([2508.09192](https://arxiv.org/abs/2508.09192), first credible faster-than-AR claim), **Free Draft-and-Verification** ([2510.00294](https://arxiv.org/abs/2510.00294), lossless parallel decoding), **FlowBlock** ([2607.17652](https://arxiv.org/abs/2607.17652), inter-block wavefront parallelism), **AdaBlock-dLLM** ([2509.26432](https://arxiv.org/abs/2509.26432), semantic-aware block size), **Enabling KV Caching of Shared Prefix for dLLMs** ([2606.07571](https://arxiv.org/abs/2606.07571)), and **CDLM** / **TiDAR: Think in Diffusion, Talk in Autoregression** (both MLSys 2026).

### 4.3 Diffusion × speculative — the hottest 2026 thread

Use a block-diffusion model as the **drafter** and an AR model as the **verifier**: drafting becomes a single parallel forward pass while output remains exactly the AR distribution. **DFlash** ([2602.06036](https://arxiv.org/abs/2602.06036)) is the flagship — a lightweight block-diffusion drafter generating a whole draft in one forward pass, conditioned on target-model context features; open source and **already an algorithm in vLLM Speculators**. The thread opened with **DiffuSpec** ([2510.02358](https://arxiv.org/abs/2510.02358)) and **SpecDiff-2** ([2511.00606](https://arxiv.org/abs/2511.00606), also MLSys 2026), which names the core problem: diffusion marginals ≠ AR conditionals. **DEER** ([2512.15176](https://arxiv.org/abs/2512.15176)) reaches 32-token drafts (5.54×); **Fail Fast, Win Big** ([2512.20573](https://arxiv.org/abs/2512.20573)) reports 4.9× overall and 1.7× over EAGLE-3; **S2D2** ([2603.25702](https://arxiv.org/abs/2603.25702)) is training-free.

Two caveats before you build on it. **DBLAST** ([2608.05448](https://arxiv.org/abs/2608.05448)) shows conditional-independence collapse degrades diffusion drafters at **temperature > 0** (xPress, [2608.02438](https://arxiv.org/abs/2608.02438), is a cheaper post-hoc refiner for the same problem). And **Accepted Prefixes Are Not All You Need** ([2607.12422](https://arxiv.org/abs/2607.12422)) is a valuable negative result: LoRA-style cheap drafter adaptation raises acceptance but **not wall-clock**. Read it before attempting the obvious shortcut.

## 5. Quantization

### 5.1 Sub-4-bit weights

**QTIP** ([2406.11235](https://arxiv.org/abs/2406.11235), NeurIPS 2024) remains the reference 2-bit PTQ design: incoherence processing makes weights approximately i.i.d. Gaussian, then trellis-coded quantization with a bitshift trellis decouples codebook size from bitrate so decoding is fast enough for a real kernel. **BCJR-QAT** ([2605.10655](https://arxiv.org/abs/2605.10655)) replaces QTIP's non-differentiable Viterbi argmax with forward-backward sum-product, giving the first credible route to *training* on a trellis code with an unchanged inference decoder. **CCQ** ([2507.07145](https://arxiv.org/abs/2507.07145)) reaches 2.0–2.75 bits with **lookup-free** encoding, demonstrated on DeepSeek-V3 — the practical answer to VQ's codebook-bandwidth problem, alongside **BiSCo-LLM** ([2607.08643](https://arxiv.org/abs/2607.08643)).

The most engine-friendly 2026 result is **GSQ** ([2604.18556](https://arxiv.org/abs/2604.18556)): VQ-class 2–3 bit accuracy using **plain symmetric group-wise scalar** weights via Gumbel-Softmax joint optimisation of grid assignment and scales, so existing INT kernels work unchanged. Also: **GPTQv2** ([2504.02692](https://arxiv.org/abs/2504.02692), asymmetric calibration matching the *full network's* output — same cost, strictly better error), **The Geometry of LLM Quantization** ([2507.18553](https://arxiv.org/abs/2507.18553), proves GPTQ is exactly Babai's nearest-plane algorithm), **VPTQ** ([2409.17066](https://arxiv.org/abs/2409.17066)), **PV-Tuning** ([2405.14852](https://arxiv.org/abs/2405.14852)).

**ParetoQ** ([2502.02631](https://arxiv.org/abs/2502.02631), Meta, NeurIPS 2025) is the paper to read if you are choosing a bit width. Comparing 1/1.58/2/3/4-bit under matched training budgets, it finds a sharp **learning transition between 2 and 3 bits** (≥3-bit stays near the pretrained distribution; ≤2-bit representations change drastically), that 1.58/2/3-bit dominate 4-bit on the accuracy-vs-size frontier, and that ~90% FP training + ~10% QAT is near-optimal. That transition is exactly why 3-bit PTQ works and 2-bit needs training.

### 5.2 Ternary and 1-bit

**BitNet b1.58** ([2402.17764](https://arxiv.org/abs/2402.17764)) defined the no-multiplies kernel model; **BitNet b1.58 2B4T** ([2504.12285](https://arxiv.org/abs/2504.12285)) is the only real open artifact to benchmark ternary kernels against. **BitNet v2** ([2504.18415](https://arxiv.org/abs/2504.18415)) adds H-BitLinear, an online Hadamard transform enabling **native 4-bit activations** — W1.58A8 wastes the 4-bit compute path on modern hardware, and this uses the same Hadamard primitive QuaRot needs, so one kernel serves both. **BitNet Distillation** ([2510.13998](https://arxiv.org/abs/2510.13998)) removes the pretrain-from-scratch blocker: convert an off-the-shelf Qwen3 to 1.58-bit with SubLN insertion, continual warm-up, and attention distillation. Also **Sherry** ([2601.07892](https://arxiv.org/abs/2601.07892), 1.25 bits by encoding ternary sparsity), **Tequila** ([2509.23809](https://arxiv.org/abs/2509.23809), fixes ternary-QAT deadzone trapping), **Sparse-BitNet** ([2603.05168](https://arxiv.org/abs/2603.05168), ternary composes with 2:4 sparsity).

### 5.3 Rotation and transform

**FlatQuant** ([2410.09426](https://arxiv.org/abs/2410.09426)) learns per-layer *affine* Kronecker-decomposed transforms optimising post-transform flatness, <1% drop at W4A4 on Llama-3-70B — the accuracy leader, at the cost of a fused per-layer transform kernel. **ReSpinQuant** ([2604.11080](https://arxiv.org/abs/2604.11080)) gets FlatQuant-like expressivity while fusing the residual rotation offline, so runtime cost stays at SpinQuant levels. **ParoQuant** ([2511.10645](https://arxiv.org/abs/2511.10645)) uses independent Givens rotations instead of dense Hadamard — far cheaper and trivially parallel, a good point for decode-bound serving.

The critical MXFP4-specific finding: **Block Rotation is All You Need for MXFP4** ([2511.04214](https://arxiv.org/abs/2511.04214)) diagnoses a mismatch between *global* Hadamard rotation and MXFP4's power-of-two per-block scaling. **If you naively port QuaRot to MXFP4 you lose most of the benefit.** **TORQ** ([2605.19561](https://arxiv.org/abs/2605.19561)) takes this further with two-level rotations matching MX's two-level scale hierarchy; **DuQuant++** ([2604.17789](https://arxiv.org/abs/2604.17789)) halves rotation overhead. **Qift** ([2606.02823](https://arxiv.org/abs/2606.02823)) exploits the fact that rotation makes weights provably Gaussian to *precompute* optimal, shift-friendly 2-bit levels. Contrarian and high-leverage if it replicates: **Massive Spikes in LLMs are Bias Vectors** ([2606.02288](https://arxiv.org/abs/2606.02288)) argues activation spikes are structural bias vectors you can subtract rather than rotate away.

### 5.4 FP4: MXFP4, NVFP4, and friends

**Pretraining LLMs with NVFP4** ([2509.25149](https://arxiv.org/abs/2509.25149), NVIDIA) is the document that made FP4 a real training format. Its four ingredients are now the standard checklist: higher precision for numerically sensitive layers, **2D block scaling** so forward and backward see identical quantized values, **Random Hadamard transforms** to disperse outliers, and **stochastic rounding on gradients**. Demonstrated on a 12B hybrid Mamba-Transformer over 10T tokens. But **Pretraining with MXFP4 on Native FP4 Hardware** ([2605.09825](https://arxiv.org/abs/2605.09825)) partially contradicts it: quantizing **Wgrad is the primary driver** of divergence, and *deterministic* Hadamard rotations — not stochastic rounding — are what stabilize training. Read both. **Full-Stack FP4** ([2607.04422](https://arxiv.org/abs/2607.04422)) extends FP4 to optimizer states and attention, BF16-comparable at 3B with 2.5–2.8× speedups.

For inference, the highest-value paper is **Unveiling the Potential of Quantization with MXFP4** ([2603.08713](https://arxiv.org/abs/2603.08713)): two pure-software techniques (Overflow-Aware Scaling, Macro Block Scaling) shrink the MXFP4↔NVFP4 accuracy gap from ~10% to **under 1%**. MXFP4 has wider hardware support and is what gpt-oss ships, so closing the gap in software means you do not need the NVIDIA-specific format. Supporting evidence: **Benchmarking PTQ under Microscaling Formats** ([2601.09555](https://arxiv.org/abs/2601.09555), ACL 2026 — MXFP8 near-lossless, MXFP4 still hard) and **INT v.s. FP** ([2510.25602](https://arxiv.org/abs/2510.25602) — **MXFP4 wins at 4-bit, MXINT8 wins at 8-bit**). **gpt-oss** ([2508.10925](https://arxiv.org/abs/2508.10925)) is the reference workload: MoE weights at 4.25 bits/param so 120B fits one 80GB GPU. Also **AdaMX** ([2608.03867](https://arxiv.org/abs/2608.03867), removes 83% of MXFP4 loss), **layer-wise FP4 sensitivity analysis** ([2603.08747](https://arxiv.org/abs/2603.08747) — MLP projections are most sensitive), **Practical FP4 Training for MoE on Hopper** ([2603.02731](https://arxiv.org/abs/2603.02731), decoupling FP4 software from Blackwell availability), and Huawei's **HiFloat4** ([2604.08826](https://arxiv.org/abs/2604.08826)).

### 5.5 QAT, activation quantization, and systems

**Gemma 3 QAT** (Google, Apr 2025, blog + checkpoints, no paper) is the clearest existence proof that ~5,000 QAT steps using the non-quantized checkpoint's probabilities as targets makes a **GGUF-native format (Q4_0) near-lossless** — 27B drops 54 GB → 14.1 GB — which is why every consumer engine adopted it immediately. **Kimi K2-Thinking** ships **native INT4 via QAT**, and Nemotron 3 ships NVFP4: checkpoints now arrive quantized, so dequant-fused GEMM is the common path, not an optimisation. Recipes and scaling: **Scaling Law for QAT** ([2505.14302](https://arxiv.org/abs/2505.14302)), **Scaling Laws for Floating-Point Quantization Training** ([2501.02423](https://arxiv.org/abs/2501.02423), ICML 2025 — how to split exponent vs mantissa bits), **Compression Scaling Laws** ([2502.16440](https://arxiv.org/abs/2502.16440), unifying sparsity and bit-width), **What Makes Low-Bit QAT Work for Reasoning LLMs?** ([2601.14888](https://arxiv.org/abs/2601.14888)), **Recover-LoRA** ([2606.04238](https://arxiv.org/abs/2606.04238), recovers 80–95% of 2-bit loss on synthetic data).

Systems: **QServe** ([2405.04532](https://arxiv.org/abs/2405.04532), MLSys 2025) remains the canonical W4A8KV4 answer to why not W4A4 — it is the format where dequant overhead disappears on current tensor cores. **LiquidGEMM** ([2509.01229](https://arxiv.org/abs/2509.01229)) is the most directly reusable artifact: a W4A8 GEMM kernel design. **MXSens** ([2607.17733](https://arxiv.org/abs/2607.17733)) reaches W4A4KV4 **without rotation**, skipping the whole online-transform tax. **DynamicPTQ** ([2606.12487](https://arxiv.org/abs/2606.12487)) gives a detector for activation-quantization collapse. **MixLLM** and **MorphServe** (runtime quantized layer swapping + KV resizing) are at MLSys 2026.

### 5.6 CPU, edge, and LUT

**T-MAC** ([2407.00088](https://arxiv.org/abs/2407.00088), EuroSys 2025) replaces dequantize-then-multiply with bit-wise table lookups for mpGEMM, 4× throughput from M2 Ultra to Raspberry Pi 5 — the reference LUT design. **bitnet.cpp** ([2502.11880](https://arxiv.org/abs/2502.11880), Microsoft) is the shipping ternary CPU kernel set. **Vec-LUT** ([2512.06443](https://arxiv.org/abs/2512.06443), MobiSys 2026) is probably the most actionable: it fixes T-MAC's weak spot under batching with a unified vector LUT and cache-aware layouts, 4.2× speedup, **integrated into llama.cpp**. **T-MAN** ([2511.11248](https://arxiv.org/abs/2511.11248)) ports the LUT trick to NPUs; **T-SAR** ([2511.13676](https://arxiv.org/abs/2511.13676)) generates lookup tables *inside SIMD registers*, avoiding the memory round-trip (up to 86× GEMV). **Pushing the Envelope on AI-PC and Intel GPUs** ([2508.06753](https://arxiv.org/abs/2508.06753)) shows hand-tuned AVX-512/AMX microkernels beat generic LUT by 2.2× over bitnet.cpp. **PolyQ** ([2607.14618](https://arxiv.org/abs/2607.14618)) is the closest academic analog to llama.cpp's k-quant per-channel bit allocation. *Notable gap: no paper analyses GGUF k-quant/imatrix directly.*

### 5.7 MoE quantization and degradation evaluation

MoE calibration is genuinely hard because rarely-routed experts see almost no tokens. **AlphaQ** ([2606.04980](https://arxiv.org/abs/2606.04980)) allocates per-expert bits **calibration-free** via heavy-tailed self-regularization; **MoEQuant** ([2505.03804](https://arxiv.org/abs/2505.03804), ICML 2025) fixes coverage with expert-balanced sampling; **GEMQ** ([2605.23078](https://arxiv.org/abs/2605.23078)) refits the router after quantization, which most methods skip. **Dynamic Expert Quantization** ([2511.15015](https://arxiv.org/abs/2511.15015)) treats expert precision as an *online* routing-traffic-driven budget — a serving design, not an offline algorithm. **Tied Trit-Planes** ([2608.08910](https://arxiv.org/abs/2608.08910)) optimises the on-disk format for SSD-streamed MoE, where storage format rather than GEMM is the bottleneck.

The evaluation results are where the surprises are. **Quantization Inflates Reasoning** ([2606.25519](https://arxiv.org/abs/2606.25519)) is the sleeper: low-bit reasoning models often **preserve accuracy while emitting substantially longer chains of thought**. Your accuracy dashboard says the 4-bit model is fine while cost-per-request silently rises. Measure tokens, not just accuracy; QAT is the best mitigation. **UniComp** ([2602.09130](https://arxiv.org/abs/2602.09130)) finds a consistent knowledge bias across pruning, quantization, and distillation — **factual recall survives compression while reasoning degrades**, which explains why RAG tolerates quantization better than agentic workloads. **Can Compressed LLMs Truly Act?** ([2505.19433](https://arxiv.org/abs/2505.19433)) finds 4-bit preserves workflow generation (1–3% drop) but degrades real agentic performance by 10–15%. Background: **Quantization Hurts Reasoning?** ([2504.04823](https://arxiv.org/abs/2504.04823)), **Give Me BF16 or Give Me Death?** ([2411.02355](https://arxiv.org/abs/2411.02355)), and safety studies ([2502.15799](https://arxiv.org/abs/2502.15799)) finding both PTQ and QAT degrade alignment.

## 6. Architecture trends that change what an engine must support

### 6.1 Hybrid linear attention — and the counter-trend

Shipped hybrids: **Qwen3-Next-80B-A3B** (Sep 2025, 12 × [3 Gated DeltaNet + 1 Gated Attention], 512 experts + 1 shared with 10 routed, 262K native → ~1M YaRN, MTP head) and **Qwen3.5-397B-A17B** (Feb 2026, same recipe scaled, asymmetric QK/V head counts in the linear path, natively multimodal). **Kimi Linear** ([2510.26692](https://arxiv.org/abs/2510.26692)) runs 3:1 **Kimi Delta Attention** to global **MLA**, where KDA extends Gated DeltaNet with *channel-wise* decay instead of a scalar gate, and the global layers are NoPE; supported in vLLM and SGLang. **Falcon-H1** ([2507.22448](https://arxiv.org/abs/2507.22448)) runs attention and Mamba-2 **in parallel** in every layer rather than alternating. **Nemotron Nano 2** ([2508.14444](https://arxiv.org/abs/2508.14444)) and **Nemotron 3** ([2512.20856](https://arxiv.org/abs/2512.20856), 1M context, LatentMoE, MTP, NVFP4). **IBM Granite 4.0** is 36 Mamba-2 : 4 attention with **NoPE**, so the KV cache is nearly negligible and memory planners tuned for uniform KV will badly mis-size. **Ling 2.5** runs 7:1 lightning attention : MLA at 1T. **Jamba Reasoning 3B** is 26 Mamba : 2 MQA at 256K.

The counter-trend is equally important. **MiniMax-M2 reverted to full GQA attention in every layer** and published why: benchmark parity at small scale hid multi-hop reasoning deficits at scale, linear attention is memory-bound even in training, and — most relevant here — three concrete serving blockers. **Low-precision state storage** (recurrent state is far more precision-sensitive than a KV cache, so INT8/FP8 KV tricks do not transfer), **prefix caching** (recurrent state does not slice or compose like KV blocks), and **speculative decoding** (called "an open and unsolved problem"). Those are exactly the three features engines take for granted. Later, **MiniMax-M3** ([2606.13392](https://arxiv.org/abs/2606.13392)) landed on *learned sparse* attention over full KV instead. The safe 2026 reading: hybrid linear attention is mainstream, but learned sparse attention is where frontier labs converged for 1M contexts.

Research feeding this: **Gated DeltaNet** ([2412.06464](https://arxiv.org/abs/2412.06464)), **RWKV-7 "Goose"** ([2503.14456](https://arxiv.org/abs/2503.14456), constant memory and time, vector-valued gating), **TTT layers** ([2407.04620](https://arxiv.org/abs/2407.04620), where the decode step contains a *gradient computation*), **MesaNet** ([2506.05233](https://arxiv.org/abs/2506.05233), a conjugate-gradient solve per step — variable iteration count breaks fixed-shape CUDA graph capture), **Comba** ([2506.02475](https://arxiv.org/abs/2506.02475)), **Log-Linear Attention** ([2506.04761](https://arxiv.org/abs/2506.04761), a logarithmically *growing* state that voids the "recurrent models have fixed memory" assumption in every hybrid memory planner), **PaTH Attention** ([2505.16381](https://arxiv.org/abs/2505.16381), data-dependent positional encoding via accumulated Householder transforms — RoPE's precomputed tables and cache-friendly relative property both disappear), **SSE** ([2507.16577](https://arxiv.org/abs/2507.16577), state size vs recall), **Mamba-3** ([2603.15569](https://arxiv.org/abs/2603.15569), complex-valued state and MIMO configuration matching Mamba-2 at half the state size — but requiring complex-arithmetic SSM kernels), **FlashMorph** ([2606.30562](https://arxiv.org/abs/2606.30562), converts Transformers to hybrids by budget-constrained layer selection, so expect *irregular per-checkpoint* hybrid patterns rather than clean 3:1 ratios). Kernel engineering: the UT-transform matrix inversion inside chunked delta-rule is the actual bottleneck — see [2607.16831](https://arxiv.org/abs/2607.16831) (1.58× on B200) and [2606.06034](https://arxiv.org/abs/2606.06034) (multiplication-only inversion so it quantizes).

### 6.2 Attention variants and MoE

**GTA and GLA** ([2505.21487](https://arxiv.org/abs/2505.21487), May 2025) are the practical MLA engineering result: Grouped-Tied Attention ties K and V states to halve KV memory transfers, and **Grouped Latent Attention is a shardable MLA** — up to 2× faster than FlashMLA and fixing MLA's classic problem that the latent cannot be tensor-parallel split.

MoE has moved to extreme sparsity: activation ratios fell from DeepSeek-V3's 5.5% to Kimi K2's 3.2% to DeepSeek-V4-Pro's 3.1%, with expert counts climbing to 384–512. At 10-of-512 the router, permutation/all-to-all, and grouped-GEMM launch overhead dominate the expert FLOPs — **MoE kernels tuned for 8-of-64 are the wrong shape.** The template is **DeepSeek-V3** ([2412.19437](https://arxiv.org/abs/2412.19437)): MLA + fine-grained experts + a shared expert + auxiliary-loss-free load balancing via router bias + MTP. **Kimi K2** ([2507.20534](https://arxiv.org/abs/2507.20534)) is 1T/32B with 384 experts; **GLM-4.5** ([2508.06471](https://arxiv.org/abs/2508.06471)) puts three dense layers before MoE routing, so dispatch does not start at layer 0.

Two structural changes deserve attention. **DeepSeek-V4** ([2606.19348](https://arxiv.org/abs/2606.19348), Jun 2026) combines Compressed Sparse Attention and Heavily Compressed Attention with **manifold-constrained hyper-connections (mHC)** and a 1,048,576-token context, needing only 27% of V3.2's per-token FLOPs and 10% of its KV at 1M. mHC ([2512.24880](https://arxiv.org/abs/2512.24880)) projects the hyper-connection mixing matrix onto doubly-stochastic matrices via Sinkhorn-Knopp, restoring the identity-mapping property plain hyper-connections broke. **This is the first architectural change since RoPE that touches every layer boundary**: instead of `x = x + f(x)`, hidden state is N parallel streams mixed by a learned matrix, so activation memory grows ~N× and kernel fusion across residual boundaries breaks. The line continues in **xHC** ([2607.14530](https://arxiv.org/abs/2607.14530), N=16) and **Motif 3** ([2608.09119](https://arxiv.org/abs/2608.09119)).

### 6.3 Windows, sinks, position, and long context

**gpt-oss** ([2508.10925](https://arxiv.org/abs/2508.10925)) alternates dense and sliding-window layers 1:1 with **learned attention sinks** — a per-head additive logit outside the window, which is a real kernel change to the softmax denominator, not a mask change. **Gemma 3** ([2503.19786](https://arxiv.org/abs/2503.19786)) uses 5:1 local:global with a 1024-token window and **different RoPE base frequencies for local vs global layers**. Xiaomi MiMo-V2-Flash uses a 128-token local window; OLMo 3 applies YaRN only on global layers; SmolLM3 puts NoPE on every fourth layer. The general lesson: **window size, RoPE base, and rope-scaling are now per-layer-group properties.** Any engine with a single global `rope_scaling` or `sliding_window` config field is already wrong. Add per-head scaling (**AdaRoPE**, [2607.19363](https://arxiv.org/abs/2607.19363)) and data-dependent PaTH and position encoding stops being one global config entirely. Reference: **Position Encoding in Transformers** survey ([2608.10021](https://arxiv.org/abs/2608.10021)).

1M context is now table stakes (Kimi Linear, Nemotron 3, MiniMax-M3, DeepSeek-V4, Llama 4 Maverick, Qwen3-Next via YaRN) — and every one of those models is hybrid-recurrent, sparse-indexed, or latent-compressed, because at 1M the KV cache rather than the weights is the deployment constraint.

### 6.4 Small models and VLMs

**Gemma 3n** uses **MatFormer** ([2310.07707](https://arxiv.org/abs/2310.07707)) nested submodels so E2B extracts from E4B, plus **Per-Layer Embeddings** streamed from host memory and cross-layer KV sharing, letting 8B raw params run at ~4B accelerator memory. **LFM2** adds gated causal-conv blocks — a *third* state type alongside KV and SSM state, and one that matters most on CPU/NPU backends. **Nemotron-Flash** ([2511.18890](https://arxiv.org/abs/2511.18890)) optimises hybrid SLMs for real-device latency rather than parameter count, finding deep-thin is *not* optimal and using learnable meta tokens so the cache starts non-empty. **Phi-4-Mini** ([2503.01743](https://arxiv.org/abs/2503.01743)) uses Mixture-of-LoRAs so modality adapters coexist. **Qwen3-VL** ([2511.21631](https://arxiv.org/abs/2511.21631)) contributes Interleaved MRoPE and **DeepStack**, which injects ViT activations from multiple layers into matching LLM layers — so the vision encoder is no longer a clean prefix-producing stage. Visual token pruning ([2510.16598](https://arxiv.org/abs/2510.16598), [2605.16359](https://arxiv.org/abs/2605.16359), [2604.02816](https://arxiv.org/abs/2604.02816)) **changes prefill token count at runtime**, interacting badly with static shapes, CUDA graphs, and prefix caching — identical images prune differently under different prompts.

## 7. Test-time compute and adaptive inference

The reasoning-model era changed the workload shape: long decode, high output-length variance, and heavy repetition inside traces. **Test-Time Scaling in Reasoning LLMs** ([2608.04001](https://arxiv.org/abs/2608.04001)) gives the taxonomy an engine should organise around, separating single-trajectory sequential scaling, leaf-level fan-out (best-of-n), and prefix-level branching — three regimes needing three different serving primitives. **Test-Time Scaling Makes Overtraining Compute-Optimal** ([2604.01411](https://arxiv.org/abs/2604.01411)) is the fleet-sizing paper: jointly optimising model size, training tokens, and sample count under a fixed *train-plus-serve* budget pushes the optimum hard into the overtraining regime. Surveys: **Stop Overthinking** ([2503.16419](https://arxiv.org/abs/2503.16419), the canonical taxonomy, actively revised through 2026), **Efficient Inference for Large Reasoning Models** ([2503.23077](https://arxiv.org/abs/2503.23077)), **Reasoning on a Budget** ([2507.02076](https://arxiv.org/abs/2507.02076), specifically on dynamic budget allocation).

**Parallel beats sequential — and it is also the batchable one.** **Sample More, Reflect Less** ([2607.28576](https://arxiv.org/abs/2607.28576)) is the controlled equal-token comparison: plain repeated sampling beats Self-Refine and Reflexion loops from 1.5B to 7B. Refinement is latency-bound and unbatchable; fan-out is neither. The best algorithm in this window is designed around that fact — **Thought-Level Beam Search (Gambit)** ([2608.08020](https://arxiv.org/abs/2608.08020)) runs beam search at thought rather than token granularity, staying batched and prefix-shared, and reports **+6.7% accuracy with 68.5% fewer tokens** than parallel sampling. Pair it with **Test-Time Scaling via Error Localization** ([2607.21453](https://arxiv.org/abs/2607.21453)), which localizes the first bad token and branches there so retries continue from a valid prefix instead of resampling from scratch, and with **GraniKV** ([2608.15584](https://arxiv.org/abs/2608.15584)), which makes shared prefixes contiguous and per-request suffixes finely paged. Counterweight: **When More Sampling Hurts** ([2606.28661](https://arxiv.org/abs/2606.28661)) identifies modal and correlation ceilings after which extra samples actively harm selection, and **Test-Time Augmentation** ([2608.09351](https://arxiv.org/abs/2608.09351)) finds input diversity converts compute to accuracy more cheaply than output diversity — but breaks prefix sharing, so measure the systems cost separately from the token cost.

**Budget control is ready to ship, and the training-free variants come first.** The s1 budget-forcing line ([2501.19393](https://arxiv.org/abs/2501.19393)) now has a unifying theory in **Reasoning as Compression** ([2603.08462](https://arxiv.org/abs/2603.08462)), which recasts efficient reasoning under a conditional information bottleneck that subsumes budget forcing and length penalties as special cases. Three training-free controllers deliver 15–69% token reductions from signals you already compute: **DART** ([2606.23181](https://arxiv.org/abs/2606.23181), samples short drafts and routes on draft agreement plus entropy — the drafts share prefix KV with the real request), **Stop When Further Reasoning Won't Help** ([2606.15070](https://arxiv.org/abs/2606.15070), an attention-state stop signal already present inside the kernel, 40% fewer tokens *with* +3.2% accuracy), and **UPAIR** ([2607.17188](https://arxiv.org/abs/2607.17188), catching underthinking as well as overthinking). Also **OS-Pruner** ([2607.11089](https://arxiv.org/abs/2607.11089), CoT truncation as optimal stopping), **Commitment Boundary** ([2606.13603](https://arxiv.org/abs/2606.13603), tokens after answer formation are epiphenomenal), **BLADE** ([2607.28966](https://arxiv.org/abs/2607.28966)), **Future Confidence Distillation** ([2607.07626](https://arxiv.org/abs/2607.07626), estimates answer confidence at *prefill* time, the enabling primitive for upfront routing). Two cautions: **Length Penalties Make CoT Less Monitorable** ([2607.09786](https://arxiv.org/abs/2607.09786)) is a real observability cost, and **Thinking Hard, Not Smart** ([2608.07968](https://arxiv.org/abs/2608.07968)) shows models cannot allocate a *shared* budget across questions — they stay greedy and order-sensitive, so the allocator has to live outside the model. Scheduling needs length prediction: **When Entropy Is Not Enough** ([2608.15592](https://arxiv.org/abs/2608.15592)) and **Robust KV Management under Length Uncertainty** ([2607.16892](https://arxiv.org/abs/2607.16892)) are the two ends of that problem. Latent CoT (the Coconut lineage, surveyed in [2509.02350](https://arxiv.org/abs/2509.02350)) gives real token savings but its faithfulness is contested ([2512.21711](https://arxiv.org/abs/2512.21711), [2606.12689](https://arxiv.org/abs/2606.12689)).

**Agentic serving is a different workload, and the model is often not the bottleneck.** **AgentSysBench** ([2608.15127](https://arxiv.org/abs/2608.15127)) characterizes agentic apps as heavyweight, stateful, and heterogeneous, finding **non-LLM components dominate latency in the majority of cases** — task-aware serving cuts latency 29–40% and caching removes 35.2% of redundant operations. **Agentic Coding in the Wild** ([2608.00101](https://arxiv.org/abs/2608.00101)) supplies rare production numbers from 3.2M Copilot sessions: **KV cache hit rate is ~90% within a turn but only ~55% across turn boundaries**, with long idle gaps that make retention expensive. The wins follow directly: cross-turn KV retention, incremental tokenization (**TokTier**, [2607.29678](https://arxiv.org/abs/2607.29678), 437× tokenization speedup and 16–34% lower TTFT — retokenizing a growing transcript every turn is a measurable tax), and speculation lifted to the **tool-call** level (**Speculate While You Reason**, [2607.25816](https://arxiv.org/abs/2607.25816), one model plays agent and speculator, predicting its next tool call while reusing prefix KV to hide tool latency; next-tool hit@1 44.1 → 61.2). See also **SPORK** ([2607.03333](https://arxiv.org/abs/2607.03333)) for speculative tool execution via prefix-cache fork.

**Prompt compression and prefix caching are adversaries.** **Cache-Aware Prompt Compression** ([2607.15516](https://arxiv.org/abs/2607.15516)) is the only work that models the interaction properly — query-agnostic compression with an explicit two-tier cost model, 49–90% savings over caching alone on production workloads. **Referential Dangling** ([2608.04569](https://arxiv.org/abs/2608.04569)) is the structural indictment of the LLMLingua selection paradigm: independent per-token selection splits dependent evidence pairs, breaking answer paths in 34–60% of examples. **The Sleeping Agent** ([2608.11775](https://arxiv.org/abs/2608.11775)) gives the failure taxonomy for gist tokens (dates and temporal facts get dropped), and **What Does Context Compression Cost an Agent?** ([2608.16370](https://arxiv.org/abs/2608.16370)) shows savings often *move* rather than disappear, as compressed agents issue more retrieval calls. Cheapest option: **linguistic-rule compressors** ([2607.25335](https://arxiv.org/abs/2607.25335)) match LM-based compressors with **no forward passes at deployment**, removing the compressor's own inference cost. Semantic caching's best current design is **LaCache** ([2608.01718](https://arxiv.org/abs/2608.01718)), which keys on both the query and the first k speculatively decoded tokens, with formal resilience against cache-collision attacks.

**Adaptive depth: the negative result matters most.** **CausalGate** ([2607.22720](https://arxiv.org/abs/2607.22720)) distills layer-skipping importance from causal interventions into *static* gates and **beats dynamic routing at zero runtime overhead** — for many workloads, routing cost and batch raggedness eat the FLOP savings. Read it before building a mixture-of-depths runtime. Where adaptive depth does pay, the looped/recursive line trades memory bandwidth for compute more gracefully: **Depth-adaptive Inference of Looped LMs** ([2608.09444](https://arxiv.org/abs/2608.09444)) builds a continuous depth-batching scheduler (1.5–1.9× throughput), **LoopUS** ([2605.11011](https://arxiv.org/abs/2605.11011)) converts an existing pretrained LLM into a looped model so recursion is a retrofit, **Soft Mixture-of-Recursions** ([2607.00774](https://arxiv.org/abs/2607.00774)) mixes across recursion steps instead of hard-routing depth (removing the ragged-batch problem), and **LoopQ** ([2605.16343](https://arxiv.org/abs/2605.16343)) is the practical blocker paper — naive PTQ compounds error across loops. **Sparse Layers in Looped Models** ([2605.09165](https://arxiv.org/abs/2605.09165)) finds Looped-MoE scales better than dense looped models, with early exits best at loop boundaries. **River-LLM** ([2604.18396](https://arxiv.org/abs/2604.18396)) solves early exit's classic KV-absence problem training-free (1.53–2.16×); **HELIOS** (MLSys 2026) does adaptive model and early-exit selection at the serving layer. The right long-term shape is **TriRoute** ([2607.06601](https://arxiv.org/abs/2607.06601)): one learned controller jointly deciding attention skipping, expert selection, and KV bit-width, instead of three independent optimisers fighting each other. Related: **WIDE** ([2607.28418](https://arxiv.org/abs/2607.28418), adaptive *width* — friendlier to dense kernels than adaptive depth), **L2A** ([2606.27743](https://arxiv.org/abs/2606.27743)), **Compute Where it Counts** ([2605.10875](https://arxiv.org/abs/2605.10875)), **Cassandra** ([2605.26558](https://arxiv.org/abs/2605.26558), 2.41× on reasoning via self-speculation with pruned weights and KV).

**Activation sparsity got a mechanistic basis and a kernel.** **Sparse Inter-Layer Dependencies of FFN Neurons** ([2607.11990](https://arxiv.org/abs/2607.11990)) supplies the structure that makes Deja Vu / PowerInfer-style activation *prediction* cheap and accurate, and **Bug or Feature²** ([2605.17659](https://arxiv.org/abs/2605.17659)) finds ordinary training already induces up to 90% activation sparsity for free — suggesting contextual sparsity is broadly applicable without ReLUfication. The perennial complaint is that no kernel realizes the theoretical savings; **Celty** ([2608.01536](https://arxiv.org/abs/2608.01536)) is a direct SpMspV kernel/SIMT co-design for simultaneous weight and activation sparsity. Sparsity also stacks: **intra-expert activation sparsity** ([2605.08575](https://arxiv.org/abs/2605.08575)) gives 2.5× layer speedup *on top of* expert routing. Security caveat: **SparSEEty** ([2608.02995](https://arxiv.org/abs/2608.02995)) reconstructs tokens at >0.95 BLEU from the input-dependent memory access patterns that sparsity optimisations create — contextual sparsity makes memory traffic a function of content, which matters in multi-tenant deployments. Also **R-Sparse** ([2504.19449](https://arxiv.org/abs/2504.19449)), **Prox** ([2607.27591](https://arxiv.org/abs/2607.27591)), **SharQ** ([2606.26587](https://arxiv.org/abs/2606.26587), activation sparsity × FP4).

**Routing and cascades.** Build against **LLMRouter** ([2608.06867](https://arxiv.org/abs/2608.06867)) and its xRouteBench rather than inventing an abstraction. **RLCascadeRouter** ([2608.15817](https://arxiv.org/abs/2608.15817)) eliminates the separate quality-estimator model whose own inference cost usually ate the cascade's savings; **WISERouter** ([2607.23765](https://arxiv.org/abs/2607.23765)) applies a fleet-level budget constraint rather than per-request routing. **PyroDash** ([2607.20327](https://arxiv.org/abs/2607.20327)) is the finest-grained cascade — learned *token-level* handoff where the small model requests large-model help mid-generation, structurally the convergence point of cascades and speculative decoding. Survey: [2603.04445](https://arxiv.org/abs/2603.04445).

**On predictive coding and the free-energy principle.** I searched this specifically, across both the predictive-coding and active-inference literatures. **There is no paper connecting predictive coding or the FEP to speculative decoding**, despite the near-exact correspondence (draft = prediction, verification = prediction error, accepted length = surprise). That gap appears genuinely unclaimed. But the framing is not empty — three 2026 papers do real work. **Affinity Is Not Enough: Recovering the Free Energy Principle in Mixture-of-Experts** ([2605.00604](https://arxiv.org/abs/2605.00604)) is the strongest: MoE routers fail at domain transitions, and adding FEP-derived temporal memory and anticipatory prediction lifts correct expert assignment at transitions from p=0.006 to **p=0.748** — a striking, directly serving-relevant result, though unreplicated. **PixelPrune** ([2604.00886](https://arxiv.org/abs/2604.00886)) uses classical residual predictive coding to prune visual tokens before the encoder for a 4.2× speedup. **Free Energy Heuristics** ([2606.15877](https://arxiv.org/abs/2606.15877)) derives *when to think* from expected-free-energy minimization — a principled basis for the adaptive-budget controllers above, rather than another heuristic. The structural thread running through 2026 is the same idea unnamed: **OasisKV** ([2608.08097](https://arxiv.org/abs/2608.08097)) uses speculative lookahead as a memory-prefetch oracle, **SparDA** ([2606.04511](https://arxiv.org/abs/2606.04511)) adds a learned Forecast projection predicting the next layer's KV needs, and **Hierarchical Latent Prediction** ([2608.05806](https://arxiv.org/abs/2608.05806)) reduces error accumulation in multi-step latent rollouts. The unexploited opening is to treat **every predictable quantity in the pipeline — KV blocks, expert routes, output length, sparse indices, tool calls — as a prediction with an explicit correction budget.** Nobody has written that generalisation down.

## 8. Serving systems

**Disaggregation is settled; elasticity is the open problem.** Nobody argues about splitting prefill and decode any more — they argue about the P:D ratio drifting under load. **Mooncake** (§2.6) is the reference architecture. **Prefill-Decode Aggregation or Disaggregation?** ([2508.01989](https://arxiv.org/abs/2508.01989)) is the clearest statement of the crossover: short prompts favour aggregation because KV transfer dominates, 8K+ prompts at high concurrency favour disaggregation. **Towards High-Goodput LLM Serving with Prefill-decode Multiplexing** ([2504.14489](https://arxiv.org/abs/2504.14489), ASPLOS 2026) makes SM-level multiplexing a real third option; **DynaServe** ([2504.09285](https://arxiv.org/abs/2504.09285)) splits requests into micro-requests so a node acts as either role per micro-request; **load-aware prefill deflection** ([2607.02043](https://arxiv.org/abs/2607.02043)) lets underloaded decode nodes absorb prefill (81% TTFT reduction). **HBM Is Not All You Need** ([2606.29986](https://arxiv.org/abs/2606.29986)) gives the strongest economic argument — disaggregation lets you buy *different silicon per phase*. **SYMPHONY** (NSDI 2026) disaggregates compute from memory rather than prefill from decode. For multimodal, **encoder-prefill-decode** three-stage splitting is becoming the norm (SGLang EPD, vLLM encoder disaggregation, **TriInfer** at MLSys 2026). Read **Beyond the Buzz: A Pragmatic Take on Inference Disaggregation** (MLSys 2026) before committing.

**MoE serving is where the hard systems work is.** DeepEP's GPU-initiated RDMA all-to-all is fast but non-portable — **UEP** (OSDI 2026) diagnoses that as rooted in tight vertical integration with specific GPU/NIC pairings and rebuilds the primitive portably. **SwiftEP** (NSDI 2026) attacks excessive buffering in prefill-stage dispatch/combine. Load balancing moved past EPLB's periodic expert swapping to per-batch optimisation: DeepSeek's **LPLB** linear-programming balancer plus SGLang's Waterfill, and **UltraEP** ([2606.04101](https://arxiv.org/abs/2606.04101), 94.3% of force-balanced throughput). The necessary counterweight is **On the Diminishing Returns of Expert Load Balancing** (MLSys 2026), alongside **Demystifying the Mixture of Experts Serving Tax** and **LYNX**. **MegaScale-Infer** ([2504.02263](https://arxiv.org/abs/2504.02263)) originated attention-FFN disaggregation and now ships as a vLLM plugin. Wide-EP **fault tolerance** became a shipping requirement in 2026 (SGLang Elastic EP, vLLM Elastic Expert Parallelism, [2605.10670](https://arxiv.org/abs/2605.10670), **ElasticMoE** [2510.02613](https://arxiv.org/abs/2510.02613)) — at EP32–EP320 a single rank failure kills the instance. Expert offloading matured too (EuroSys 2026 fine-grained offloading, **MoE-APEX** at ASPLOS 2026, **fMoE** [2502.05370](https://arxiv.org/abs/2502.05370), **PROBE** [2602.00509](https://arxiv.org/abs/2602.00509), **MoE-SpeQ** [2511.14102](https://arxiv.org/abs/2511.14102)), with routing-prediction quality as the whole ballgame. **KTransformers** (SOSP 2025) and **Achieving Cloud-Grade SLOs for Local MoE Inference** (OSDI 2026, [2606.10493](https://arxiv.org/abs/2606.10493)) show MoE sparsity makes CPU-GPU hybrid viable in a way dense models never allowed. **ELDR** ([2607.00466](https://arxiv.org/abs/2607.00466)) makes decode routing expert-locality-aware; **Moebius** ([2606.26607](https://arxiv.org/abs/2606.26607)) switches between expert and tensor parallelism at runtime.

**Memory management.** **vAttention** ([2405.04437](https://arxiv.org/abs/2405.04437), ASPLOS 2025) uses CUDA VMM to keep KV *virtually* contiguous while physically dynamic, so unmodified attention kernels work — the reference argument that PagedAttention's kernel tax is avoidable. **Jenga** and **DiffKV** (SOSP 2025) handle heterogeneous KV, which hybrid/MLA/sliding-window models now force. **KUNSERVE** (EuroSys 2026) inverts eviction policy by dropping *parameters* rather than KV under pressure. **Prism** (OSDI 2026) uses GPU memory ballooning across co-resident models after finding production traces show bursty model-group activation. **MoonBright** (OSDI 2026) attacks the allocator/TLB costs that bottleneck VMM-based KV management.

**Scheduling.** **JITServe** (NSDI 2026) designs for the fact that you do *not* have accurate length predictions; **Robust KV Cache Management under Output Length Uncertainty** ([2607.16892](https://arxiv.org/abs/2607.16892)) does the principled version with Wasserstein distributionally-robust optimisation (56% cost reduction vs fixed-quantile). **FastServe** (NSDI 2026) brings iteration-level preemption, which matters because long-decode reasoning requests are the dominant tail-latency source. **Simple Is Better: Multiplication May Be All You Need** (OSDI 2026) is a strong "your learned scheduler is overfit" result. **ServeGen** (NSDI 2026) is the trace generator you should benchmark against instead of synthetic Poisson arrivals. **Fairness-Aware and Latency-Controllable Scheduling for Chunked-Prefill** ([2606.09061](https://arxiv.org/abs/2606.09061)) shows chunked prefill quietly redistributes latency between tenants.

**Agentic and RL changed the scheduling unit.** **Agentix** (NSDI 2026), **Pie** and **PrefillOnly** (SOSP 2025), **Murakkab** (OSDI 2026), **HexAGenT** ([2605.16637](https://arxiv.org/abs/2605.16637)), and **ForeCache** (MLSys 2026) all converge: the independent request is the wrong abstraction — sessions, workflows, and DAGs are. **TraceLab** ([2606.30560](https://arxiv.org/abs/2606.30560)) characterises 4,300 coding-agent sessions. On the RL side the inference engine is now half of a training system, with OSDI'26 (**Weave**, **RollArt**, **Seer**) and NSDI'26 (**RollPacker**, **RLBoost**, **DistRS**) papers on rollout long-tail and trainer/rollout co-scheduling. Four concrete engine requirements fall out of production RL work: weight-sync bandwidth (P2P RDMA weight transfer updating 1T parameters in seconds), bitwise train/inference consistency, token-in-token-out to avoid retokenization drift, and native async weight-sync APIs.

**Kernels.** The **megakernel** result (Hazy Research, May 2025) — fusing ~100 kernels of a forward pass into a single on-GPU interpreter for ~2.5× over vLLM on H100 and >3.5× on B200 — established that at low batch size, *kernel-boundary overhead* rather than FLOPs or bandwidth is the binding constraint. The follow-ups solve the blocker: **Event Tensor** ([2604.13327](https://arxiv.org/abs/2604.13327), MLSys 2026) encodes task dependencies so megakernels tolerate dynamic shapes; **Fleet** ([2604.15379](https://arxiv.org/abs/2604.15379)) handles multi-die GPUs; **RaMP** ([2604.26039](https://arxiv.org/abs/2604.26039)) and **UniEP** ([2604.19241](https://arxiv.org/abs/2604.19241)) extend it to MoE. The practical ship-today alternative is maximising CUDA-graph coverage. Also at MLSys 2026: **HipKittens** (AMD), **ParallelKittens**, **TokenWeave** ([2505.11329](https://arxiv.org/abs/2505.11329)), **Flashlight** (compiler extensions for attention variants), **FlashInfer-Bench**; and **FlashInfer** ([2501.01005](https://arxiv.org/abs/2501.01005), MLSys 2025) remains the reference for exposing sparse/paged attention as one JIT-compiled, load-balanced engine rather than N bespoke kernels.

**Multi-LoRA and structured output.** **ELORA** (HPCA 2026) co-places adapter weights and KV cache, which usually have two independent policies competing for the same memory. **InfiniLoRA** ([2604.07173](https://arxiv.org/abs/2604.07173)) disaggregates LoRA execution entirely. For constrained decoding, **XGrammar** ([2411.15100](https://arxiv.org/abs/2411.15100), MLSys 2025, up to 100× via context-independent token prechecking) and **XGrammar 2** ([2601.04426](https://arxiv.org/abs/2601.04426)) retarget at *agentic dynamic grammars* where tool schemas change per turn; **Pre³** ([2506.03887](https://arxiv.org/abs/2506.03887), ACL 2025) uses deterministic pushdown automata for 40% lower TPOT. Mask computation is now well under token-generation cost — grammar support is no longer a throughput excuse.

## 9. Edge and on-device

**PowerInfer-2** ([2406.06282](https://arxiv.org/abs/2406.06282)) remains the reference design for flash-resident, sparsity-driven mobile inference. The most important 2026 reframing is **Sereno** (OSDI 2026): concurrent LLM inference sharply raises *foreground app jank rate*, so the metric that decides whether on-device inference ships is frame-deadline adherence, not tok/s. Three independent 2026 studies ([2607.05475](https://arxiv.org/abs/2607.05475), [2605.27435](https://arxiv.org/abs/2605.27435), [2603.23640](https://arxiv.org/abs/2603.23640)) find **NPUs win prefill and often lose decode**, with sustained-load thermal behaviour invalidating burst benchmarks — distrust the headline number. NPU-first designs consolidated at MobiSys 2026 (**ShadowNPU**, **Vec-LUT**, power-efficient inference), storage-aware KV offload matured (**KVSwap**, **DUAL-BLADE** [2604.26557](https://arxiv.org/abs/2604.26557)), and on-device speculative decoding coupled to DVFS and energy rather than latency alone (**OmniDraft** [2507.02659](https://arxiv.org/abs/2507.02659), **Lever** [2605.16786](https://arxiv.org/abs/2605.16786), **GELATO** [2605.10124](https://arxiv.org/abs/2605.10124), **MemSpec** [2608.10362](https://arxiv.org/abs/2608.10362)). Mobile MoE is the most plausible route to strong on-device models since only a fraction of weights move from flash per token (**CoMoE** [2508.09208](https://arxiv.org/abs/2508.09208), **EdgeXpert** [2608.05303](https://arxiv.org/abs/2608.05303), **DraftExpert** [2607.24434](https://arxiv.org/abs/2607.24434)). Note that llama.cpp, MLC-LLM, ExecuTorch, and MNN-LLM remain largely *unpublished* — they appear in the literature only as baselines, most systematically in the engine survey below.

## Trends and open problems

**Five things changed between 2025 and 2026.**

*Sparse attention won, and the indexer became the bottleneck.* Every frontier open model now ships either learned sparse attention over full KV (DeepSeek DSA, MiniMax MSA, LongCat, GLM-5) or a linear/softmax hybrid. Sparse attention is no longer an optimisation you bolt on; it is part of the checkpoint, with its own trained parameters. The consequence is that **an engine needs an indexer subsystem** — scorer, top-k, gathered attention — that is pluggable, because the 2026 literature is almost entirely about swapping the indexer. Cross-layer index reuse is the most-replicated cheap win.

*Memory capacity replaced compute as the frontier constraint.* HiSparse, OasisKV, SparDA, KARAT, SAC, and TraCT all independently argue that keeping the full KV in HBM so every token stays *selectable* is the actual wall, and that the fix is host-memory-backed hierarchical caches with lookahead prefetch. Strata's finding that hierarchical caching goes I/O-bound on fragmented layouts is the practical corollary, and CXL's cache-line granularity is a natural fit for sparse access. Expect tiered, prefetch-driven KV to become standard rather than exotic.

*Uniformity assumptions are gone.* A single model now mixes KV cache, linear/SSM state, conv state, and latent KV; window sizes, RoPE bases, and rope-scaling are per-layer-group; NoPE layers coexist with RoPE layers; sparse patterns are per-GQA-group; and mHC may make the residual stream N parallel streams. Memory planning, paging, eviction, offload, and prefix caching all have to become per-layer-type. Any engine with one global config field for these is already wrong.

*The scheduling unit moved from the request to the session.* Agentic and RL workloads made prefix reuse, cross-turn KV lifecycle, and rollout long-tail into first-class systems problems. Two operational findings deserve emphasis: for agents, **delay compaction** until future queries are visible rather than compacting at turn boundaries; and speculation should be **disabled under compute-bound load** rather than tuned.

*Compression's costs are subtler than benchmarks show.* Eviction fails on multi-turn, multi-instruction, and reasoning-faithfulness axes while aggregate accuracy looks fine. Quantization preserves factual recall but degrades reasoning, and low-bit reasoning models silently emit longer chains of thought. The FlashAttention-compatibility filter kills most attention-score-based methods regardless. The healthy direction is compression with an explicit accuracy knob or certificate — vAttention's approximation guarantees, WitCert's runtime distortion bounds, error certificates for eviction — so quality becomes an SLO rather than a hyperparameter.

**Open problems worth building into.** Speculative decoding for stateful models needs recurrent-state rollback, not KV truncation, and remains unsolved at production quality. Prefix caching for recurrent state is a named blocker with no clean answer. Diffusion LLMs are a real serving target now (Mercury at ~1100 tok/s, DiffusionGemma, LLaDA2.0 at 100B) but need a separate execution mode, and whether WeDLM's causal-attention reformulation holds up decides how much of your existing stack transfers. Multi-tenant prefix-cache timing leakage is a demonstrated attack with only new defences. Cross-model KV transfer, if it replicates, changes routing economics for tiered deployments. And the unified allocator — one budget shared across eviction, quantization, prompt compression, and agent memory under a rate-distortion objective — has been proposed (TriRoute, MoE-nD, [2607.08032](https://arxiv.org/abs/2607.08032)) but not built.
